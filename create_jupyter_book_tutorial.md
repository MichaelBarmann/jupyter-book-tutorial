# Tutorial: Creating a Jupyter Book

This tutorial walks through creating a new Jupyter Book from scratch, previewing it locally, customizing the title/branding, and tracking the book with Git and GitHub.

The commands below assume you are working on Windows using **Anaconda Prompt**. If your regular PowerShell already recognizes `python`, `pip`, and `jupyter book`, then you can use PowerShell instead.

---

## 1. Choose a location for your Jupyter Books

First, decide where you want to keep your Jupyter Book projects. For example:

```text
C:/Users/mbarm/Documents/Documents/01_GradSchool/03_code/jupyter_books
```

Navigate there in Anaconda Prompt:

```cmd
cd C:/Users/mbarm/Documents/Documents/01_GradSchool/03_code/jupyter_books
```

Check your current location:

```cmd
cd
```

You should see a path ending in:

```text
.../03_code/jupyter_books
```

**Screenshot suggestion:** Take a screenshot of the terminal after running `cd`, showing that you are inside the `jupyter_books` folder.

---

## 2. Create a new folder for the book

Create a folder for the new book. For example, to create a book called `git-tutorial`, run:

```cmd
mkdir git-tutorial
cd git-tutorial
```

Check your current location:

```cmd
cd
```

You should now be inside:

```text
.../jupyter_books/git-tutorial
```

**Screenshot suggestion:** Show the terminal after creating and entering the new book folder.

---

## 3. Initialize the Jupyter Book

Run:

```cmd
jupyter book init
```

When prompted:

```text
Would you like to run jupyter book start now? (Y/n)
```

type:

```text
n
```

and press Enter.

This creates a configuration file called:

```text
myst.yml
```

Check the folder contents:

```cmd
dir
```

You should see:

```text
myst.yml
```

**Screenshot suggestion:** Show the terminal output after `jupyter book init` and `dir`, with `myst.yml` visible.

## 4. Create the homepage

Every book needs a main page. Create `index.md`:

```cmd
notepad index.md
```

Paste in starter content such as:

```markdown
# Git Tutorial

Welcome to my Git tutorial.

This book is a place for notes on:

- Git basics
- GitHub basics
- repositories
- staging and committing
- pushing and pulling
- common terminal commands

## Goal

The goal of this book is to build a clear, beginner-friendly reference for using Git and GitHub in my coding workflow.
```

Save and close Notepad.

Then check the folder contents:

```cmd
dir
```

You should now see:

```text
index.md
myst.yml
```

**Screenshot suggestion:** Show the folder contents after creating `index.md`.

---

## 5. Configure the book title and header text

Open the configuration file:

```cmd
notepad myst.yml
```

A basic `myst.yml` file may look like this:

```yaml
# See docs at: https://mystmd.org/guide/frontmatter
version: 1
project:
  id: your-existing-project-id
  title: Git Tutorial
  # description:
  # keywords: []
  # authors: []
  # github:
  # To autogenerate a Table of Contents, run "jupyter book init --write-toc"
site:
  template: book-theme
  title: Git Tutorial
  options:
    logo_text: Git Tutorial
    hide_footer_links: true
```

Important notes:

- Keep the existing `project.id` generated by Jupyter Book.
- The `project.title` is the title of the book project.
- The `site.title` is the title used by the website.
- The `logo_text` controls the text shown at the far left of the page header.
- YAML indentation matters. Use spaces, not tabs.

Save and close the file.

Check the file contents:

```cmd
type myst.yml
```

**Screenshot suggestion:** Show the edited `myst.yml` file in Notepad or show the terminal output from `type myst.yml`.

## 6. Preview the book locally

Start the local preview server:

```cmd
jupyter book start
```

You should see output similar to:

```text
Server started on port 3000!

http://localhost:3000
```

Open this address in your browser:

```text
http://localhost:3000
```

You should see your Jupyter Book homepage.

**Screenshot suggestion:** Take a screenshot of the book open in your browser, showing the title and homepage content.

## 7. Stop the local server when you are done previewing

While the server is running, the terminal will show server messages and will not accept normal commands.

To stop the server, click inside the terminal and press:

```text
Ctrl + C
```

Once the normal prompt returns, you can run commands again.

**Screenshot suggestion:** Optional: show the terminal while the local server is running, especially the `http://localhost:3000` line.

## 8. Add another page

Create a new Markdown file:

```cmd
notepad basic_workflow.md
```

Paste something like:

```markdown
# Basic Git Workflow

A common Git workflow is:

```bash
git status
git add .
git commit -m "Describe the change"
git push
```

## What the commands mean

- `git status` shows what has changed.
- `git add .` stages all changed files.
- `git commit -m "..."` creates a snapshot.
- `git push` uploads committed changes to GitHub.
```

Save and close the file.

Now the folder contains:

```text
basic_workflow.md

## 9. Add the new page to the table of contents

Open `myst.yml`:

```cmd
notepad myst.yml
```

Add a `toc:` section under `project:`:

```yaml
project:
  id: your-existing-project-id
  title: Git Tutorial
  toc:
    - file: index.md
    - file: basic_workflow.md
```

The full file might now look like:

```yaml
# See docs at: https://mystmd.org/guide/frontmatter
version: 1
project:
  id: your-existing-project-id
  title: Git Tutorial
  toc:
    - file: index.md
    - file: basic_workflow.md
  # description:
  # keywords: []
  # authors: []
  # github:
  # To autogenerate a Table of Contents, run "jupyter book init --write-toc"
site:
  template: book-theme
  title: Git Tutorial
  options:
    logo_text: Git Tutorial
    hide_footer_links: true
```

Save and close the file.

Restart the book:

```cmd
jupyter book start
```

Refresh the browser. The new page should appear in the navigation/sidebar.

**Screenshot suggestion:** Show the browser with the sidebar/navigation containing both pages.

## 10. Remove the bottom “Made with MyST” label

By default, the book theme may show a “Made with MyST” label near the bottom of the sidebar. To remove it, create a custom empty sidebar footer file.

First stop the server with:

```text
Ctrl + C
```

Then create a folder for custom site files:

```cmd
mkdir _site
```

Create an empty sidebar footer file:

```cmd
cd _site
type nul > primary_sidebar_footer.md
cd ..
```

Now open `myst.yml`:

```cmd
notepad myst.yml
```

Add the `parts:` section under `site:`:

```yaml
site:
  template: book-theme
  title: Git Tutorial
  options:
    logo_text: Git Tutorial
    hide_footer_links: true
  parts:
    primary_sidebar_footer: _site/primary_sidebar_footer.md
```

Save and close the file.

Restart the book:

```cmd
jupyter book start
```

Refresh the browser. The bottom “Made with MyST” label should be gone.

**Screenshot suggestion:** Show a before/after comparison: one screenshot with the “Made with MyST” label and one after it has been removed.

## 11. Create a `.gitignore`

The `_build/` folder is generated automatically when the book is built or previewed. Usually, you should not track `_build/` with Git.

Create a `.gitignore` file:

```cmd
notepad .gitignore
```

Paste:

```gitignore
_build/
.ipynb_checkpoints/
.DS_Store
```

Save and close the file.

Check the folder:

```cmd
dir
```

You should see:

```text
.gitignore
index.md
myst.yml
_site
_build
```

The `_build/` folder exists locally, but Git will ignore it.

**Screenshot suggestion:** Show the `.gitignore` contents or the terminal output from `dir`.

```text

## 13. Make the first commit

Stage the files:

```cmd
git add .
```

Check the status:

```cmd
git status
```

Commit the files:

```cmd
git commit -m "Initial Jupyter Book setup"
```

Rename the branch to `main`:

```cmd
git branch -M main
```

Check the status:

```cmd
git status
```

You should see:

```text

nothing to commit, working tree clean
```

## 14. Create the GitHub repository

Go to GitHub and create a new repository.

Suggested settings:

```text
Repository name: git-tutorial
Description: Notes on using Git and GitHub
Visibility: Public or Private
Initialize this repository with:
  README: No
  .gitignore: No
  license: No
```

Do not add a README, `.gitignore`, or license on GitHub if you already created files locally.

After creating the repo, copy the HTTPS URL. It should look like:

```text
https://github.com/your-username/git-tutorial.git
```

**Screenshot suggestion:** Show the GitHub “Create a new repository” page with the repository settings selected.

## 15. Connect the local repo to GitHub

Back in the terminal, add the GitHub repo as the remote:

```cmd
git remote add origin https://github.com/your-username/git-tutorial.git
```

Check that the remote was added:

```cmd
git remote -v
```

You should see:

```text

## 16. Push the book to GitHub

Run:

```cmd
git push -u origin main
```

The `-u origin main` part sets the upstream branch. After this first push, future pushes can usually be done with:

```cmd
git push
```

Check the status:

```cmd
git status
```

You should see:

```text
On branch main
Your branch is up to date with 'origin/main'.

nothing to commit, working tree clean
```

## 18. Normal workflow after setup

Once the book is set up, the normal editing workflow is:

```cmd
jupyter book start
```

Then edit Markdown files, refresh the browser, and repeat until the page looks right.

When you are happy with your changes:

```cmd
git status
git add .
git commit -m "Describe the update"
git push
```

A typical session looks like:

```text
1. Start the book locally.
2. Edit one or more `.md` files.
3. Refresh the browser to preview changes.
4. Stop the server with Ctrl + C.
5. Commit and push the changes.
```

  index.md
  basic_workflow.md

  images/

```text

```text

```text

```

```markdown

## 20. Common mistakes

### Mistake 1: Trying to open `_build/site/index.html`

In Jupyter Book v2, the preview workflow is usually:

```cmd
jupyter book start
```

rather than manually opening an `index.html` file.

### Mistake 2: Forgetting to stop the server

If the terminal is showing server logs, stop the server with:

```text
Ctrl + C
```

before running Git commands.

### Mistake 3: Tracking `_build/`

If `git status` shows `_build/`, make sure `.gitignore` contains:

```gitignore
_build/
```

### Mistake 4: YAML indentation problems

YAML uses indentation to define structure. This is good:

```yaml
site:
  template: book-theme
  options:
    logo_text: Git Tutorial
```

This is risky:

```yaml
site:
  template: book-theme
  options:
     logo_text: Git Tutorial
```

The second version may work sometimes, but it is better to use consistent two-space indentation.

### Mistake 5: Typos in custom part filenames

If `myst.yml` says:

```yaml
primary_sidebar_footer: _site/primary_sidebar_footer.md
```

then the file must be named exactly:

```text
primary_sidebar_footer.md
```

A typo like:

```text
primary_sitebar_footer.md
```

will cause a warning.
